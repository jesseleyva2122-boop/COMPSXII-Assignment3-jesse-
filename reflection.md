# Reflection - Object Simulator Assignment

## 1. Structs vs Classes

This assignment showed me how C can simulate object-oriented programming even though C does not have classes like Python. The `Character` struct stores data such as the name, health, and level, along with function pointers that act like methods. I had to manually create those function pointers and assign them during initialization. I also had to pass a `Character*` into each function so the function knows which object it is working with. In Python, the language handles the object reference and method lookup automatically when I write something like `hero.attack()`. In this C program, calling `character->attack(character)` uses the function pointer stored inside the struct. This helped me understand that a method call is ultimately a function being selected and given access to the object's data.

## 2. Inheritance Implementation

Warrior and Mage simulate inheritance by containing a `Character` struct as their first member. This gives both specialized types the basic character information while also allowing them to add their own data, such as a Warrior's strength or a Mage's mana. The base structure being first is important because it allows a pointer to a Warrior or Mage to be treated as a `Character*` when using the shared interface. Python makes this much simpler with class syntax, such as `class Warrior(Character)`, and automatically handles the relationship between the parent and child classes. In C, I had to build that relationship manually with composition, initialization functions, and casts. Python's approach is easier to read and maintain, while C gives the programmer more direct control over the underlying memory layout and behavior.

## 3. Understanding OOP Mechanics

Function pointers are what make polymorphism possible in this program. The `attack` pointer can point to the basic Character attack, the Warrior attack, or the Mage attack. The program can then store all three types in an array of `Character*` pointers and make the same `attack` call, while each character produces different behavior. The most challenging part was understanding how a `Character*` can be converted back into a `Warrior*` or `Mage*` when the specialized attack function needs access to fields that only exist in the derived structure. I also had to pay attention to the Mage's mana because the attack changes the object's state each time it is called. Systems programmers might use these patterns because C does not provide built-in classes, but structs and function pointers still allow programmers to organize complex data and behavior. This approach is useful when working on game engines, operating systems, embedded systems, or other software where direct control and predictable performance are important. Overall, the assignment helped me understand that some features Python provides automatically can be built manually in C, but doing so requires more careful management of the data, pointers, and relationships between objects.
